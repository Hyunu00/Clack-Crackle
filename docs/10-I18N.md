# 10 — 현지화 (i18n)

이 문서는 **언어를 나중에 추가할 수 있게 만드는 것**이 목적이다.
출시 시점의 언어 목록보다 "추가 절차가 싸다"는 성질이 중요하다.

`docs/09-DEV-ENV.md` 의 "반드시 지켜야 하는 것 ①" 을 구현한 문서다.

## 게임 제목 (🟢 확정)

| 언어 | 제목 |
|---|---|
| 한국어 | **나만 없어 왁뿌볼** |
| **그 외 전 언어** | **Clack & Crackle** |

`Clack` = 키캡 타건음, `Crackle` = 왁스 파열음. 두 소재를 하나씩 맡는다.
둘 다 의성어라 유행어가 없다 (`docs/06-DECISIONS.md` 의 Q2 결정과 일치).

한국어만 현지화 제목으로 유행어를 태운다. **영문 주제목이 스토어 URL 과
앱 식별자를 결정하므로 현지화 제목의 변경 비용은 훨씬 낮다.**
"되돌리기 비용이 낮은 자리에 유행을 태운다"는 Q2 원칙 그대로다.

밈 형식이라 다른 언어로 옮길 수 없다. **한국어 외에는 번역하지 말고
`Clack & Crackle` 을 그대로 쓴다.**

주의: 한국어 제목이 9자다. 타이틀 화면 로고를 640×360 안에 앉힐 때
영문보다 폭이 넓다. `docs/03-ART.md` 의 로고 작업 시 두 벌을 상정할 것.

1. **RTL** — UI 레이아웃 전체가 좌우 반전된다. HUD 가 HTML 이라

점유율 상위 10위 안에도 없다.

## 언어를 추가하는 절차

**이 절차가 7단계를 넘어가면 설계가 잘못된 것이다.**

```
1. 이 문서의 티어 표에 한 줄 추가 (스팀 코드 + BCP-47 + 폰트 프로필)
2. src/i18n/{code}.json 생성 — 내용은 {} 한 줄
3. src/i18n/locales.ts 의 LOCALES 배열에 한 줄 추가
      { code, steamCode, label, font, dir, tier }
4. 폰트 프로필 확인 — 그 문자를 픽셀 폰트가 커버하는가
      커버 못 하면 font 를 'fallback' 으로
5. npm test — 번역 커버리지가 "de  0/232 (0%)" 처럼 찍힌다
6. 번역해서 채운다. 미번역 키는 en 으로 표시되므로 부분 번역 상태로 커밋해도 된다
7. 스팀: 스토어 페이지 현지화 + "지원 언어" 표에 체크
```

**2번에서 `en.json` 을 복사하지 말 것.** 복사하면 값이 전부 영어로 채워져서
커버리지가 **100% 로 잘못 잡힌다.** 번역이 하나도 안 됐는데 다 된 것처럼
보이는 게 제일 나쁘다. **빈 `{}` 로 시작하면** 폴백이 알아서 영어를 띄우고,
`npm test` 가 남은 키를 정확히 세어준다.

**설정 화면의 언어 목록은 `LOCALES` 를 읽어서 그린다.**
언어를 추가할 때 UI 코드를 고치는 일이 있으면 안 된다.

## 문자열을 추가하는 절차

언어가 아니라 **키**를 늘릴 때다. 화면을 만들다 보면 계속 생긴다.

```
1. src/i18n/en.json 에 키 추가          ← 키 집합의 기준은 항상 en.json 이다
2. src/i18n/ko.json 에 같은 키 추가
      이름이 아직 미정이면 값에 "[그 키]" 를 그대로 넣는다
      예:  "sys.rebirth": "[sys.rebirth]"
3. 코드에서 t("그 키") 로 쓴다. 한국어 문자열을 코드에 직접 쓰지 않는다
4. npm test — 나머지 7개 언어의 누락 목록에 새 키가 붙는다. 정상이다
```

**나머지 7개 언어는 지금 건드리지 않는다.** 폴백이 en 을 띄우고, 번역할
때가 되면 `npm test` 가 뽑아주는 목록이 그대로 번역 발주서가 된다.

### 콘텐츠를 늘릴 때도 같다

출시 후 **왁뿌볼 종류 추가가 가장 싼 업데이트 카드**다 (`docs/00-CONCEPT.md`).
51번째 종류를 넣는다면:

```
en.json / ko.json 에  "ball.type.051"  추가
assets/balls{tps}/ball_051.png 추가 → npm run assets
core/content/balls.ts 의 희귀도 테이블 count 를 +1
```

**콘텐츠 데이터는 `nameKey` 만 갖는다.** 문자열을 직접 갖지 않는다.

### 값에 숫자를 끼워 넣을 때

```json
{ "ui.roulette.cost": "{n} G" }
```
```ts
t("ui.roulette.cost", { n: 100 })   // "100 G"
```

토큰은 `{이름}` 형식이고, **원문과 번역문의 토큰 집합이 같은지 테스트가 검사한다.**
번역가가 `{n}` 을 빼먹거나 `{N}` 으로 바꾸면 거기서 걸린다.

## 구조

```
src/i18n/
  index.ts      t(key, params?) / setLocale / onLocaleChange / detectLocale
  locales.ts    LOCALES 배열. 언어 추가 시 유일하게 고치는 코드 파일
  en.json       ★ 키 집합의 기준. 나머지는 전부 이걸 따라간다
  ko.json
  zh-CN.json  ru.json  ja.json  es.json  pt-BR.json  de.json  fr.json
```

게임용이라 i18next 는 과하다. JSON 로드 + `t(key)` 로 충분하다.

**JSON 은 `import.meta.glob` 로 통째로 집어간다.** `index.ts` 에 언어별
`import` 문이 없는 이유다. 손으로 import 를 쓰기 시작하면 "JSON 1개 +
`locales.ts` 1줄" 이라는 성질이 그 자리에서 깨진다.

### LOCALES 한 줄의 생김새

```ts
{ code: "de", steamCode: "german", label: "Deutsch",
  font: "latin", dir: "ltr", tier: "T1" }
```

| 필드 | 뭘 넣나 |
|---|---|
| `code` | BCP-47. **`src/i18n/{code}.json` 파일 이름과 정확히 같아야 한다** |
| `steamCode` | 스팀 스토어 언어 코드. 아래 티어 표에 있다 |
| `label` | 설정 화면에 그대로 그린다. **그 언어 사용자가 읽는 표기로** (`Deutsch`, `日本語`) |
| `font` | 폰트 프로필. 아래 폰트 매트릭스 |
| `dir` | `ltr` / `rtl`. 지금 등록된 9개는 전부 `ltr` |
| `tier` | 키 누락을 에러로 볼지 경고로 볼지를 이걸로 가른다 |

### 번역하지 않는 키 — `NO_TRANSLATE`

`locales.ts` 에 목록이 있다. 지금은 `game.title` 하나다.

**다른 언어 JSON 에 넣지 않는 게 의도다.** 폴백이 en 을 쓰므로 자동으로
`Clack & Crackle` 이 나오고, 한국어만 `ko.json` 에서 덮어쓴다.
누락 키 테스트도 이 목록은 건너뛴다. 넣지 말 것.

### 폴백 규칙

```
t(key)
  1. 현재 로케일에 있으면        → 그 값
  2. 없으면 en.json              → 영어
  3. en 에도 없으면              → "[key]" 를 그대로 출력
```

3번을 빈 문자열로 만들지 말 것. **미번역이 화면에서 눈에 띄어야 한다.**
누락 키는 콘솔에 모아서 한 번에 찍는다 — 그게 번역 체크리스트가 된다.
(`docs/04-AUDIO.md` 의 빈 사운드 키 처리와 같은 방식이다.)

### 키 규칙

```
game.title               제목 — 키 하나다. ko 만 덮어쓰고 나머지는 en 폴백
sys.*                    시스템 용어 12
grade.* / rarity.*       개체 등급 5 + 종류 희귀도 5
ball.type.001 ~ 050      왁뿌볼 종류 50
cap.001 ~ 024            키캡 24
skill.<id>.name / .desc  스킬트리 8 × 2
auto.<id>.name / .desc   자동화 3 × 2
ach.<ID>.name / .desc    업적 26 × 2
ui.*                     버튼, 라벨, 설정 62
```

현재 **233개**. `docs/10-I18N.md` 의 분량 추정(400~500)에서 `ui.*` 가 화면을
만들면서 늘어난다.

**`game.title` 을 `game.title.ko` / `game.title.en` 두 키로 쪼개지 않는다.**
쪼개면 화면 코드가 "지금 언어가 뭐지" 를 보고 둘 중 하나를 골라야 하고,
그 순간 **언어를 추가할 때 UI 코드를 고치게 된다.** 키 하나로 두면 폴백 규칙이
알아서 "한국어면 현지화 제목, 나머지는 `Clack & Crackle`" 을 만든다.

콘텐츠 데이터는 **`nameKey` 만 갖는다.** 문자열을 직접 갖지 않는다.

```ts
{ id: 1, nameKey: "ball.type.001", rarity: 1, baseValue: 40 }   // O
{ id: 1, name: "사과", rarity: 1, baseValue: 40 }                // X
```

## 폰트 매트릭스

**픽셀 폰트의 상업 이용 라이선스와 글리프 커버리지를 반드시 확인할 것.**
`docs/03-ART.md` 의 에셋 목록에도 같은 항목이 있다.

| 프로필 | 대상 | 요구 글리프 |
|---|---|---|
| `latin` | en de fr es pt-BR pl tr it vi id | 라틴 + **확장 라틴** |
| `cyrillic` | ru uk | 키릴 |
| `ko` | ko | 한글 |
| `ja` | ja | 가나 + 상용한자 |
| `zh` | zh-CN zh-TW | 중문 상용자 |
| `fallback` | ar th | 시스템 폰트. 픽셀 톤 포기 |

**확장 라틴을 빠뜨리지 말 것.** 자주 사고가 나는 지점이다.

```
독일어   ä ö ü ß
프랑스어  é è ê ç à ù
스페인어  ñ á í ó ú ¿ ¡
폴란드어  ł ą ę ś ż ź ć ń
터키어   ı İ ş ğ ç ö ü      ← 점 없는 ı 와 점 있는 İ 가 별개 글자다
포르투갈어 ã õ ç á â
베트남어  성조 결합 기호 다수 — 커버리지가 가장 넓다
```

**CJK 픽셀 폰트는 선택지가 극히 적다.** 한/중/일이 한 폰트로 안 되면
프로필별로 다른 폰트를 물리는 구조를 미리 잡을 것. 나중에 붙이면 렌더러를
뜯어야 한다.

## 번역 분량

| 대상 | 개수 | 난이도 |
|---|---|---|
| UI · 시스템 문자열 | 약 150~250 | 낮음 |
| **왁뿌볼 종류** | **50** | **높음 — 고유명사** |
| **키캡** | **24** | **높음 — 고유명사** |
| 스킬트리 노드 이름 + 설명 | 11 × 2 | 중간 |
| 업적 이름 + 설명 | 26 × 2 | 중간 |
| 등급 · 희귀도 표기 | 10 | 낮음 |
| 스토어 페이지 | 1 세트 | 중간 |

총 400~500 키. 클리커라 분량 자체는 작다.

**비용의 대부분은 고유명사 74개다.** 이름에는 말장난과 톤이 들어가서
기계번역이 특히 나쁘다. `docs/08-NAMING.md` 에서 한국어 이름을 확정할 때
**번역 가능성을 같이 볼 것.** 옮길 수 없는 말장난은 그 언어에서 다른
말장난으로 바꿔야 하고, 그건 번역이 아니라 재창작이라 비싸다.

**스토어 페이지 번역이 게임 내 번역보다 ROI 가 높다.** 노출에 직접 걸린다.
T2 언어는 스토어만 먼저 번역하는 선택지도 있다.

| 검사 | 지금 |
|---|---|
| `LOCALES` ↔ JSON 파일이 짝이 맞는가 | **에러** |
| 등록 안 된 JSON 이 굴러다니는가 | **에러** |
| `en.json` / `ko.json` 에 빈 값이 있는가 | **에러** |
| `ko.json` 이 `en.json` 과 키 집합이 같은가 | **에러** |
| `{n}` 토큰이 원문과 번역문에서 같은가 | **에러** |

### 커버리지를 왜 아직 에러로 안 잡나

T1 7개 언어가 빈 파일이라 지금 에러로 잡으면 **`npm run check` 가 첫날부터
빨간불**이고, 그러면 커밋 게이트로 못 쓴다 (`CLAUDE.md` 절대 규칙 10).
미번역 키는 en 으로 폴백되므로 **게임은 정상 동작하고 버그가 아니다.**

번역이 들어오면 리포트 숫자가 저절로 0 에 수렴한다. 0 이 된 뒤
`tests/i18n.test.ts` 의 `STRICT_KEY_COVERAGE` 를 `true` 로 바꾸면
그때부터 T0/T1 은 실패, T2 이하는 경고가 된다. **출시 전에 반드시 켤 것.**

### 번역 진행률 보는 법

```bash
npm test
```

```
[i18n] T1 de  0/232 (0%)  누락: sys.rebirth, sys.gold, … 외 212개
[i18n] 이름 미정 232/233 — docs/08-NAMING.md
```

앞줄이 **번역 발주서**, 뒷줄이 **이름 확정 진행률**이다. 둘은 다른 작업이다 —
이름을 먼저 정하고(`docs/08-NAMING.md`), 그 다음에 번역한다.

### 게임을 켜고 보는 법

화면에 실제로 필요했는데 번역이 없던 키는 콘솔에 모아서 한 번에 찍는다.
JSON 전체가 아니라 **그 화면이 진짜 쓰는 키만** 나오므로 우선순위가 보인다.

### 화면 검증

`npm run shot` 을 **언어별로** 돌릴 것. 텍스트 길이가 언어마다 다르다.

```
독일어    영어 대비 약 1.3배. UI 가 가장 잘 터진다
러시아어  영어 대비 약 1.2배
CJK      짧지만 글자가 크다
```

**독일어에서 안 터지면 대체로 다 통과한다.** 독일어를 기준으로 볼 것.

`tests/visual.spec.ts` 가 `ko / en / de` 를 돌면서 `shots/10-locale-*.png` 를
찍는다. 언어를 늘리려면 그 파일 맨 아래 배열에 코드를 한 줄 더하면 된다.

```ts
for (const code of ["ko", "en", "de"]) { … }
```

언어 전환은 디버그 훅으로 한다. 설정 화면이 생기기 전에도 촬영이 된다.

```ts
window.__game.i18n.setLocale("de")
window.__game.i18n.missing()    // 그 화면이 실제로 못 찾은 키
```
