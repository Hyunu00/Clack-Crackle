# 04 — 사운드

**이 게임에서 가장 중요한 문서다.**

플레이어가 사는 것은 왁뿌볼이 부서지는 소리다. 숫자는 그 소리를 언제
들려줄지 조절하는 장치일 뿐이다. 밸런스가 별로면 지루한 게임이지만,
사운드가 별로면 아무것도 아닌 게임이 된다.

**음원 조달은 직접 하기로 확정.** 이 문서는 필요 목록과 구현 규칙만 정의한다.

---

## ⚠️ 50종 × 5등급 사운드를 다 녹음하지 말 것

아트와 같은 직교 구조를 쓴다.

| 요소 | 제작물 |
|---|---|
| 종류별 파괴음 | 50종 × 3~5변주 |
| 등급 스팅 (위에 겹침) | 5개 |

250세트가 아니라 **50세트 + 5스팅**이다.

50종 녹음도 부담이면 **희귀도 그룹 단위로 묶어도 된다.**
★1 18종이 같은 계열 소리를 쓰고 종류별로 피치만 다르게 하는 식.
플레이어는 ★5 소리가 특별하다는 것만 알면 된다.

## 사운드 목록

### 코어

| 키 | 설명 | 변주 |
|---|---|---|
| `cap_press` | 키캡 타건 | 4~6 |
| `ball_crack_<단계>` | 균열 **1~5단계** (공용) | 단계당 3 |
| `ball_shatter_<종류>` | 완전 파괴 | 종류당 3~5 |
| `ball_spawn` | 왁뿌볼이 필드에 나옴 | 2 |
| `coin` | 골드 획득 | 3 |

**균열음은 5종을 다 만든다. 다만 한 판에 다 쓰이진 않는다.**
기본 단계 수가 **4**이고 플레이어가 설정에서 3~5 로 바꿀 수 있다
(2026-09 갱신). N 이 5보다 작으면 5종 중 균등하게 골라 쓰고
**마지막은 항상 `ball_crack_5`** 로 끝난다.

단계 정의는 `docs/02-ECONOMY.md` 의 "균열 단계" 가 원본이고,
아트 오버레이도 같은 방식으로 5장 중 N장을 쓴다 (`docs/03-ART.md`).

**전체가 약 3초다.** 설정별 단계 길이:

| 단계 수 | 단계당 |
|---|---|
| 3 | 1.0초 |
| **4 (기본)** | **0.75초** |
| 5 | 0.6초 |

**`ball_crack_N` 을 0.75초 기준으로 녹음할 것.** 3단계 설정(1.0초)에서
살짝 여유가 생기고 5단계(0.6초)에서 살짝 겹치는 정도가 적당하다.
너무 길게 녹음하면 5단계 설정에서 서로 밟는다.

> ★ 단계 수는 **감각 설정이지 밸런스 설정이 아니다.** 어떤 값을 골라도
> 파괴 시간(3초)과 골드는 같다. 소리 밀도만 바뀐다.

### 끊어 누르기 (🟢 2026-09 확정)

꾹 누르다 손을 떼면 **진행률이 그 자리에 멈춘다.** 다시 누르면 이어서 간다.
소리 쪽에서 중요한 건 이것이다:

- **뗄 때** — 진행 중이던 연속 균열음을 자연스럽게 끊는다. 뚝 자르면
  거슬리므로 짧은 페이드아웃을 둘 것
- **다시 누를 때** — 소리가 **새로 난다.** 멈춘 단계에서 이어서 시작하지,
  1단계부터 되감지 않는다
- 짧게 끊어 누르는 리듬으로 소리를 만드는 플레이가 나온다. **그게 이 게임의
  정체성이다** — 끊어 눌렀을 때 소리가 안 나거나 뭉개지면 그 놀이가 죽는다

**왁뿌볼에는 개별 타격음이 없다.** 연타를 없앴으므로(2026-09) 부수는
소리는 균열음과 파괴음뿐이다. `cap_press` 는 키캡 전용이고 그대로 남는다.

### 등급 스팅 (파괴음 위에 겹침)

`sting_rare` / `sting_epic` / `sting_legendary` / `sting_supreme`

**Supreme 스팅에 예산을 쓸 것.** 클립으로 퍼지는 건 이 순간이다.

### 앰비언스

`amb_room` — 조용한 방 톤. 아주 작게.

**키캡별 타건음:** 24종 각각 다르게 할지, 등급별 5종만 쓸지는 음원 확보
상황에 맞춰 결정. 코드는 `keycap.soundKey` 로 참조하므로 어느 쪽이든 대응된다.

## 구현 규칙

**사운드 정의는 데이터다.** `src/core/content/audio.ts` 에 목록으로만 두고,
재생 코드가 파일명을 직접 알지 못하게 한다.

`src/audio/` 는 `GameEvent` 를 구독해서 재생한다. `core` 는 오디오를 모른다.

### 필수 처리

1. **랜덤 변주** — 직전에 쓴 인덱스를 피한다
2. **피치 변주** — 재생마다 ±5%. 이것만으로 반복감이 크게 준다
3. **동시 재생 상한** — 자동 파괴가 켜지면 소리가 폭발한다.
   같은 키는 짧은 시간 내 N개까지. 넘으면 볼륨 감쇠.
   ★ **상한에 걸렸다고 파괴음을 통째로 버리지 말 것** (5번 참조)
4. **꾹 누르기가 유일한 수동 파괴다** (연타 없음, 2026-09).
   누르고 있는 동안 진행률이 계속 오르고, 단계가 넘어갈 때마다
   `ball_crack_N` 이 이어져 **하나의 끊기지 않는 파열음**으로 들려야 한다.
   **약 3초에 N단계가 다 지나간다** — 기본 4단계면 단계당 0.75초다
   (`docs/02-ECONOMY.md` "파괴 1회 = 약 3초" / "균열 단계").
5. **자동 파괴에도 소리는 난다** — 수동보다 조용하게, 그러나 **끄지 않는다.**
   자동이 켜진 후반이 플레이 시간의 대부분이다. 거기서 소리를 죽이면
   **게임이 후반에 무음이 된다.** 이 게임이 파는 게 그 소리다.
   시끄럽지 않게 만드는 건 볼륨과 동시 재생 상한으로 하고, 재생 자체를
   생략하지 말 것.
6. **볼륨 슬라이더** — 마스터/효과음/BGM 분리. ASMR 게임에서 필수
7. **포맷** — `.ogg` 우선, `.m4a` 폴백. `.wav` 는 배포에 쓰지 말 것

라이브러리: **howler.js 2.2.4** (`npm i howler` + `npm i -D @types/howler`)

`src/core/content/audio.ts` 는 데이터만 두고, `src/audio/` 가 howler 를 감싼다.
`core` 는 howler 를 import 하지 않는다.

### 음원이 없을 때

`public/sfx/` 에 파일이 없으면 조용히 넘어가고 콘솔에 **비어 있는 키 목록**을
찍는다. 그게 녹음 체크리스트가 된다.

## BGM

ASMR 게임에서 BGM 은 방해가 될 수 있다.
**기본 꺼짐, 설정에서 켤 수 있게.**

무료 음원을 쓴다면 라이선스 확인 필수.
"무료"와 "상업 이용 가능"은 다르다.

## 접근성

청각 의존 게임이므로 대체 경로가 필요하다.

- 균열/파괴는 시각적으로도 명확히
- 등급은 소리 없이도 구분 가능해야 함
- "중요 사운드 시 화면 플래시" 옵션 고려
