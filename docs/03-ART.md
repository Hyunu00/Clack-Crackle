> 🟢 **2026-09 픽셀아트 → 캐주얼 아트로 전환.** 근거와 포기한 것은
> `docs/06-DECISIONS.md` "아트 스타일 — 픽셀 → 캐주얼". 이 문서는 그 결정
> 이후의 규격이다. 아래 수치는 전환 시점에 논리 해상도가 사라지면서 정한

## 해상도 규격

| 항목 | 값 |
|---|---|
| 기준(디자인) 해상도 | **1920 × 1080** — 출력 해상도를 그대로 기준으로 쓴다 |
| 화면 배율 | 창 크기에 맞춰 **소수 배율**로 부드럽게 스케일 |
| 키캡 표시 크기 | **216 × 216** (세로 1/5 — 픽셀아트 시절과 동일 비율 유지) |
| 왁뿌볼 표시 크기 | 120 × 120 |
| 필드 슬롯 | 144 × 144 |
| 도감 썸네일 | 72 × 72 |
| 필터 | linear (기본값, 코드에서 건드리지 않는다) |
| 좌표 | 제약 없음. 반응형 레이아웃 허용 |

**에셋은 표시 크기의 2배 해상도로 제작한다** (`CLAUDE.md` 절대 규칙 4).
레티나/고DPI 화면에서 확대해도 흐려지지 않게 하기 위해서다.

| 요소 | 표시 크기 | 제작(2x) 크기 |
|---|---|---|
| 키캡 | 216×216 | **432×432** |
| 왁뿌볼 | 120×120 | **240×240** |
| 필드 슬롯 | 144×144 | **288×288** |
| 도감 썸네일 | 72×72 | **144×144** |

**표시 크기가 픽셀아트 시절(72×72 ×3, 40×40 ×3 …)의 실제 화면 크기와
동일하다.** 화면상 왁뿌볼·키캡의 물리적 크기, 마우스 이동 거리는 안 변한다
— `01-OPEN-QUESTIONS.md` Q3(키캡↔필드 거리)의 판단은 그대로 유효하다.
아트 스타일 전환이 게임플레이 레이아웃까지 흔드는 게 아니라는 뜻이다.

🟢 코드 반영 완료 — `src/render/app.ts` 의 `VIEW_W`/`VIEW_H` 가 1920/1080,
`fitScale()` 이 소수 배율을 그대로 돌려주고, `tests/env.test.ts` 가 이걸 단언한다.

## 왁뿌볼 — 250개를 그리지 않는 법

종류 50 × 등급 5 = 250조합인데, 실제 제작물은 **60장**이다.
이 원칙은 아트 스타일과 무관하다 — 캐주얼로 바뀌어도 그대로 간다.

| 요소 | 담당 | 제작물 |
|---|---|---|
| 종류 | 모양 | 스프라이트 **50** |
| 등급 | 색 + 이펙트 | 틴트/필터 **5** |
| 균열 | 파괴 단계 | **공용 오버레이 5** |

**균열을 종류별로 그리지 말 것.** 왁스 껍질이 깨지는 표현이라
반투명 오버레이 5장을 종류 위에 얹으면 된다. 소재상으로도 자연스럽다.
종류별로 그리면 250프레임이 된다.

**5장을 다 제작하되, 한 판에 다 쓰이진 않는다** (🟡 2026-09 갱신).
기본 단계 수가 **4**이고 플레이어가 설정에서 3~5 로 바꾼다. N 이 5보다
작으면 5장 중 균등하게 골라 쓰고, **마지막은 항상 5번**으로 끝난다 —
파괴 직전 모습이 설정과 무관하게 같아야 하기 때문이다.

단계 정의는 `docs/02-ECONOMY.md` 의 "균열 단계" 가 원본이고, 사운드도 같은
방식이다 (`docs/04-AUDIO.md`). **아트 제작 분량은 설정과 무관하게 5장이다.**

**꾹 눌러 부수는 게 유일한 수동 방식이다** (연타 없음, 2026-09).
누르는 동안 오버레이가 연속으로 갈아끼워진다. 한 장 한 장 툭툭 바뀌는 게
아니라 **이어지는 한 동작**으로 보여야 한다 — 단계 사이에 짧은 크로스페이드나
균열이 번지는 연출을 넣는 걸 권한다.

### ★ 캐주얼 아트에서 틴트가 자연스럽게 먹으려면 — 레이어 분리

픽셀아트는 단색 실루엣이라 등급 틴트(초록/보라/금)를 그냥 곱해도 자연스러웠다.
**캐주얼 아트는 그림 자체에 하이라이트·그림자가 이미 그려져 있어서**, 색상만
곱하는 틴트를 하면 하이라이트까지 초록/보라로 물들어 부자연스럽다.

**종류 스프라이트를 두 레이어로 나눠서 그릴 것:**

```
base    베이스 컬러  — 형태와 고유색. 등급 틴트가 여기만 곱해진다
shade   셰이딩       — 하이라이트/그림자/윤곽선. 무채색(흑백/알파)에 가깝게.
                       곱하기(multiply)·오버레이 블렌드로 base 위에 얹는다.
                       틴트의 영향을 안 받는다
```

이렇게 두면 "등급 틴트 + 이펙트"라는 `CLAUDE.md` 규칙 5번의 직교 구조가
캐주얼 그림에서도 그대로 성립한다. 한 장짜리 완성 일러스트로 그리면
등급별 색만 바꾸는 게 불가능해서 250장을 다 그리게 된다.

| 등급 | 표현 |
|---|---|
| Common | 원본 색 |
| Rare | 초록 틴트 + 얇은 외곽선 강조 |
| Epic | 보라 틴트 + 은은한 발광 |
| Legendary | 금 틴트 + 발광 + 반짝 파티클 |
| Supreme | **레인보우 색상 순환** + 상시 파티클 |

### Supreme — 레인보우 색상 순환 (🟢 확정, 2026-09)

**무지개 색이 계속 움직인다.** 정지 상태에서도 색이 흐르고 있어야 한다.

- 구현은 **색조(hue) 회전**이다. 텍스처를 여러 장 굽지 않는다 —
  `CLAUDE.md` 규칙 5번(직교)을 그대로 지킨다
- 베이스 컬러 레이어에만 hue 를 돌리고 셰이딩 레이어는 그대로 둔다.
  안 그러면 하이라이트까지 무지개가 되어 형태가 뭉개진다
- 캐주얼 아트라 색이 부드럽게 이어져서 픽셀 팔레트 사이클보다 훨씬 쉽다
- **속도가 관건이다.** 너무 빠르면 싸구려 티가 나고 눈이 아프다.
  느리게 흐르는 쪽이 비싸 보인다 — `npm run shot` 으로는 판단이 안 되니
  실제로 움직이는 걸 보고 정할 것

50개 중 2종뿐인 ★5 와 헷갈리지 말 것. 이건 **개체 등급** Supreme 이고
어떤 종류에서도 나올 수 있다.

**★ 희귀도는 왁뿌볼 자체에 표시하지 않는다.** 도감에서만 별로 보여준다.
화면의 왁뿌볼은 등급 색만 입는다. 두 축이 화면에서 겹치면 혼란스럽다.

## AI 생성 파이프라인 (캐주얼 전환의 이유)

`docs/06-DECISIONS.md` 참조. 핵심만 요약하면:

- 캐주얼(귀여운 아이콘 톤)은 이미지 생성기가 학습 데이터를 가장 많이
  가진 영역이라 스타일 일관성이 잘 나온다
- 픽셀아트는 AI 결과물이 정확한 격자에 안 맞아서, 결국 Aseprite 로
  손수 정리하는 작업이 원본을 그리는 것과 맞먹는다
- **50종 사이 실루엣 구분은 여전히 리스크다.** 스타일은 일관돼도
  AI 생성 아이콘들은 "동글동글 귀여운 덩어리"로 수렴하는 경향이 있다.
  생성 후 반드시 도감 배치로 늘어놓고 실루엣만 흑백으로 비교해볼 것
  (아래 "작업 규칙"의 실루엣 검증과 동일한 기준)

## 팔레트

`src/render/palette.ts` 와 `index.html` CSS 변수 두 곳. **항상 같이 고칠 것.**

```
--case   #14161c   케이스 (배경)
--plate  #272d3a   플레이트
--cap    #e8e2d4   키캡 상단 (PBT 베이지)
--amber  #f2b705   골드 / 강조
--jade   #6ec3c1   보조
```

배경을 어둡게 유지하는 이유: 왁뿌볼이 부서질 때 파편과 빛이 튀어야 하는데
밝은 배경에서는 안 보인다. 이 이유는 스타일과 무관하게 그대로 유효하다.

**왁뿌볼 50종은 이 팔레트에 매이지 않는다.** 알록달록해야 소재에 맞다.
다만 배경/UI 와 충돌하지 않게 채도 상한은 둘 것.

캐주얼 아트는 픽셀아트와 달리 **그라데이션·부드러운 그림자**를 쓸 수 있다.
과하게 그려서 소재(왁스 문구점 완구)의 단순한 즐거움을 배신하지 않을 것 —
`docs/00-CONCEPT.md` 의 톤 밸런스("과하게 세련되면 소재를 배신")는 스타일이
바뀌어도 그대로 적용된다.

## 에셋 파이프라인 (AssetPack)

에셋이 90장을 넘는다. 개별 PNG 로 로드하면 요청 90번에 Pixi 배칭도 못 쓴다.

```
assets/               ← raw PNG 를 여기에
  balls{tps}/
  keycaps{tps}/
  cracks{tps}/
  ui{tps}/
  fx{tps}/
        │  npm run assets
        ▼
public/atlas/         ← 폴더당 스프라이트시트 1장(png+webp) + .json
```

**폴더 이름의 `{tps}` 는 오타가 아니다.** AssetPack 은 이 태그가 붙은 폴더만
스프라이트시트로 묶는다. 태그를 빼면 PNG 가 그냥 복사만 되고 아틀라스가
안 나온다. 새 에셋 폴더를 만들 때도 `{tps}` 를 붙일 것.

런타임 코드는 아틀라스에서 **프레임 이름**으로 꺼내 쓴다.
`core/content/` 의 `spriteKey` 가 그 프레임 이름과 일치해야 한다.

**프레임 이름은 확장자를 포함한 파일명 그대로다** (`nameStyle: "short"`).

```
assets/balls{tps}/ball_001.png   →   프레임 이름 "ball_001.png"
```

→ `spriteKey: "ball_001.png"` 로 쓴다. 확장자를 빼면 못 찾는다.
`{tps}` 폴더끼리 같은 파일명이 있으면 AssetPack 이 충돌 경고를 낸다.
`docs/03-ART.md` 의 파일명 규칙(`ball_NNN.png` 등)을 지키면 충돌하지 않는다.

**압축은 AssetPack 기본값을 그대로 쓴다** (png quality 90 / webp quality 80).
픽셀아트 시절엔 손실 압축이 격자를 뭉갰어서 무손실을 강제했는데, 캐주얼
아트는 그 제약이 없다. `.assetpack.js` 에 압축 설정을 아예 안 넘긴다.

PNG 를 추가하거나 고친 뒤에는 반드시 `npm run assets` 를 다시 돌릴 것.

## 작업 규칙

- **2배 해상도로 그린다.** 표시 크기 그대로 그리면 고DPI 화면에서 흐려진다
- 안티에일리어싱 켜기 — 부드러운 곡선이 정상이다 (픽셀아트 시절과 반대)
- 파일명: `cap_NNN.png`, `ball_NNN.png`, `crack_N.png`, `fx_*.png`, `ui_*.png`
  `core/content/` 의 키와 정확히 일치할 것
- **왁뿌볼 50종은 실루엣이 서로 구분되어야 한다.** 색만 다르면 도감에서
  구별이 안 된다. 채색 전에 흑백 실루엣만 늘어놓고 확인할 것 —
  AI 생성 아이콘은 스타일이 통일될수록 실루엣이 수렴하는 경향이 있다
- 종류 그림은 **베이스 컬러 / 셰이딩** 두 레이어로 분리 (위 "틴트가
  자연스럽게 먹으려면" 참조). 하나로 합쳐 그리면 등급 틴트가 안 먹는다

도구: 이미지 생성 AI(스타일 레퍼런스 고정) + Photoshop/Figma 로 레이어 정리·배경 제거.
직접 손으로 그릴 경우 Procreate/Photoshop/Figma 등 일반 래스터·벡터 툴 사용.
